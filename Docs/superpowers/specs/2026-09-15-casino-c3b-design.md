# フェーズC-3b設計: /duel(PvP)+ 月次シーズン制

**状態: ユーザー承認済み(2026-09-14 の骨格 + 2026-09-15 の細目は親が決定)。** 承認された骨格 —
`/duel @相手 <bet>` は**コイントス**(相手がボタンで受諾、ハウスの取り分なし、両者から預かる)、
シーズンは**月次**・**純利順**・**上位 3 名にチップを賞与**・**残高はリセットしない**。
C-1 / C-2 / C-3a の規則をそのまま引き継ぐ(通貨は `int64` 切り捨て、ギルドごと独立、単一ライター、
永続化 → 表示の順、読み取り点で正規化)。ループ(`TASKS.md` の C3B 系)はこの文書を仕様として読み、
反復の中で設計を再検討しない。矛盾を見つけたら `blocked/<task>.md` に書いて止まる。

## 1. 目的と範囲

C-2 までは「1 人 対 胴元」だけだった。C-3b は**人 対 人**の勝負と、**月ごとに区切って競う理由**を足してフェーズ C を閉じる。

| 入るもの | 入らないもの |
|---|---|
| `/duel @相手 <bet>`(コイントス、受諾ボタン、3 分で失効) | サイコロ・じゃんけん等の他の PvP 種目 |
| 月次シーズン(純利の集計・順位・上位 3 名への賞与・切り替え) | シーズン中の残高リセット、過去シーズンの全履歴(直近 1 件だけ保持) |
| `/season`(今の順位表・自分の順位・残り日数・前シーズンの結果) | ギルドをまたぐ集計、シーズン専用の通貨 |

## 2. 資金の契約(C-3a §8 の続き。**実装前にここを読む**)

- **duel は 2 人の間のゼロサム**。ハウスの取り分は無い(コイントスなので胴元有利を作らない)。
  両者から `bet` を預かり(`OpenGame`)、勝者へ `2 × bet` を払う(`SettleGame`)。敗者の精算は `payout = 0`。
  **合計は不変** — 預かり 2×bet が勝者へ移るだけで、通貨は湧かない。**消える経路は口座の上限ひとつだけ**で、
  勝者の空きが `2 × bet` に足りないときに入り切らない分が消える(次の次の項)。上限に当たらない通常の範囲では
  合計はまったく動かない。
- **賞与は新規発行**(デイリーボーナスと同じく Bot が配る)。1 位 10,000 / 2 位 5,000 / 3 位 2,500 チップ。
  これは**意図的な通貨の発生**であり、設計書にそう書く(保存則の例外として明示する。C-3a の「消える 2 か所」と対になる)。
- 口座の上限(`MaxChips`)で賞与が入り切らない分は**捨てる**(スロット等の配当と同じ。宝くじの賞金と違い、
  「他の 1 人へ移る」形にはならないので、プールへ送る規則は適用しない)。
- **上限は配当を止める理由にしない** — `SettleGame`・`AcceptDuel` は入り切る分だけ入れて残りを捨て、精算そのものは
  必ず成功する。拒否にすると、同じ取引で閉じた月次切り替えごと巻き戻り、その切り替えが払う賞与こそが口座を
  埋めた張本人なので、再試行が拒否された状態を作り直す — 預かり(`Escrow`)を抱えた手が永久に閉じなくなる。
  上限は**行き先の性質**であって、取引を失敗させる条件ではない。
- `SeasonNet` は**通貨ではない**(順位付けのための集計値)。上限で捨てられた配当があっても `SeasonNet` は
  「実際に口座へ入った額」で数える — 表示上の順位と手持ちの増減を食い違わせないため。

**実測(duel のゼロサムと賞与の発行額)**: 1,000 チップずつ持つ 2 人が 200 チップで duel を決着させると、勝者 1,200・敗者 800 になり、
2 人の `Chips + Escrow` の合計は始まりの 2,000 のまま動かない(`TestAcceptDuel_MovesThePotToTheWinnerAndKeepsTheTwoAccountsSummedUnchanged`
が保存後のファイルから数える)。`SeasonNet` も +200 / −200 で合計 0 になる — 順位の集計値が duel で漂わない。ずれるのは上限に当たった
ときだけで、`MaxChips − 100` の挑戦者が 200 を賭けて勝つと受け取るのは 400 ではなく余裕ぶんの 300、`SeasonNet` も +200 ではなく
実際に増えた +100 になる(`TestAcceptDuel_WinnerAtTheCapTakesOnlyWhatFitsAndSeasonNetCountsThat`)。賞与は対照的に**通貨が増える**側で、
1 ギルドの 1 回の切り替えが発行するのは最大 10,000 + 5,000 + 2,500 = 17,500 チップ、それが月に 1 回きり(1,000 チップずつ持つ 6 人の
うち純利 1,000 / 500 / 500 の 3 人が表彰台なら、残高は 11,000 / 6,000 / 3,500 になり、4 位と負け越しと未参加は 1,000 のまま:
`TestStore_SeasonRollover_ClosesMonthPaysPodiumAndZeroesEveryAccount`)。上限で入り切らない分は捨てるので発行額が 17,500 を超えることはなく、
`MaxChips − 3,000` にいた 1 位が受け取るのは 3,000、`MaxChips` に座った 2 位は 0、`SeasonRank.Bonus` に残るのは表の額ではなく**入った額**
(`TestStore_SeasonRollover_BonusCappedAtMaxChips_RecordsWhatLanded`)。

## 3. 純利(`SeasonNet`)の定義

- `UserAccount` に `SeasonNet int64`(`json:"season_net,omitempty"`)を足す。**ゲームの勝敗だけ**を積む:
  スロット・ハイ&ロー・ブラックジャック・duel・宝くじ。1 回ごとに `SeasonNet += (実際に受け取った額 − 賭けた額)`。
- **含めない**: デイリーボーナス、両替、`/casino-admin mint`、シーズン賞与、ウェルカムボーナス。
  (配られた分で順位が決まると「遊んだ人」が上に来ない。)
- 負の値を取りうる(負けている人はマイナス)。`[-MaxChips, MaxChips]` へ読み取り点で正規化する(C-3a の規律)。

## 4. シーズン

- `GuildEconomy` に:
  ```go
  SeasonMonth string        `json:"season_month"`          // 進行中のシーズン "2026-09"("" = 未開始)
  LastSeason  *SeasonResult `json:"last_season,omitempty"` // 直近に閉じた 1 件だけ
  ```
  ```go
  type SeasonResult struct {
      Month   string        // 閉じたシーズン "2026-09"
      Ranks   []SeasonRank  // 上位 3 名(純利の降順、同点は UserID 昇順)
      Players int           // 純利が 0 でなかった人数
  }
  type SeasonRank struct { UserID string; Net int64; Bonus int64 } // Bonus は実際に入った額
  ```
- **切り替えは日次ロールオーバーの中**(C-3a と同じ `ensureTodayRateIndexLocked`、同じ `Update`)。
  JST の**月**が `SeasonMonth` と変わったら閉じる: 上位 3 名を決めて賞与を入れ、`LastSeason` を書き、
  全口座の `SeasonNet` を 0 にし、`SeasonMonth` を今月にする。**9 時ではなく日付境界(深夜)で切り替える** —
  レートと同じ境界にして「月初の 0 時から新シーズン」を分かりやすくする。
- 取りこぼし防止: ロールオーバーに乗るので、月初に Bot が落ちていても起動後の最初のコマンドで切り替わる。
  未開始(`SeasonMonth == ""`)のギルドは、賞与を配らずに今月を開始するだけ(初回は集計対象が無いため)。
- 掲示: 9 時掲示の embed に「🏆 シーズン(今月)」フィールド(上位 3 名と自分ではなく全体の順位)。
  シーズンが閉じた日は、**別メッセージ**で結果を公開で祝う(スロットの大当たり・宝くじの当選と同じ流儀)。

## 4.5 duel(`/duel @相手 <bet>`)

- ベット幅は 10〜1,000 チップ(他のゲームと同じ)。相手が自分自身・Bot なら「❌ 自分自身とは対戦できません」
  「❌ Bot とは対戦できません」。どちらかに進行中のゲーム(`Escrow > 0`)があれば従来の文言で断る。
- 挑戦: 挑戦者から `bet` を預かり(`OpenGame(guild, challenger, "duel", bet)`)、公開メッセージに
  「⚔️ <@相手> への挑戦(N チップ)」と **「⚔️ 受ける」「🚫 断る」** のボタンを出す。押せるのは**相手だけ**
  (所有者検査は C-2 の `requireSessionOwner` を「受け手」向けに使う。`Session.UserID` は挑戦者なので、
  盤面の状態に受け手の ID を持たせて判定する)。
- 受諾: 受け手からも `bet` を預かる。ここで残高不足・進行中ありなら受諾は失敗し、**挑戦者の預かりは返さない**
  (盤面は生きたまま。別の誰かが受けることはできないので、断られるか失効するまで待つ)。
  受諾できたらコイントスを引き(乱数源は注入可能)、勝者へ `2 × bet`、敗者へ `0` を精算し、結果を編集で見せる。
- 辞退(🚫)と失効(3 分、C-2 の掃除人): **挑戦者の預かりを全額返す**(`SettleGame(payout = bet)`)。
  受け手は何も預けていないので動かさない。失効時のメッセージは「⌛ 時間切れ — 挑戦は取り下げられました」。
- 表示は C-2 の流儀(決着でボタンを無効化して残す、精算が先・表示が後、通信エラーは秘匿ヘルパー経由)。

## 5. コマンドと表示

| コマンド | 内容 | 表示 |
|---|---|---|
| `/duel <相手> <bet>` | コイントスで 1 対 1。相手の受諾ボタン付き | 公開 |
| `/season` | 今月の上位 10 名・自分の順位と純利・残り日数・前シーズンの結果 | 公開 |

- `/help` と `README.md` の一覧に 2 本を足す。`/balance` に「今月の純利」を 1 行足す。

## 6. エラーハンドリング(既存の文言に揃える)

- ベット範囲外・残高不足・進行中あり・ギルド外: C-1 / C-2 と同じ文言。
- 他人が挑戦ボタンを押した: 「❌ この挑戦はあなた宛てではありません」(ephemeral)。
- 受諾時に受け手のチップが足りない: 「❌ チップが足りません(現在: N枚)」(ephemeral、盤面は残す)。

## 7. テスト方針

- duel(純粋): コイントスの決定性(乱数注入)、勝敗の精算額、辞退・失効の返金、自分自身/Bot の拒否。
- シーズン(純粋): 上位 3 名の選抜(同点は UserID 昇順)、賞与の額、純利が 0 の人を数えない、月またぎの検出。
- Store: 保存則(duel は 2 人の合計が不変、賞与は発行として計上)、`SeasonNet` の増減がゲームの勝敗とだけ一致、
  切り替えで全口座の `SeasonNet` が 0 になる、同じ月に二度閉じない、未開始ギルドは賞与なしで開始、
  読み取り点での正規化(`SeasonNet` の範囲)、並行 duel の受諾で二重精算が起きない。
- 掲示: フィールドと祝いメッセージの純粋関数テスト。コマンドは `Handle()` から切り出した純粋関数で。

## 8. アーキテクチャ

```
internal/casino/duel.go       コイントスと精算(純粋、discordgo 非依存)
internal/casino/season.go     純利の集計・順位・賞与(純粋)
internal/casino/store.go      duel の預かり/精算、SeasonNet の更新、月次切り替え(ロールオーバー内)
internal/commands/duel.go     /duel + 受諾/辞退ボタン
internal/commands/season.go   /season
internal/commands/casino_announce.go   シーズンのフィールドと結果の祝い
```

`cmd/bot/main.go` は**変更しない**(duel は C-2 のボタン基盤と掃除人に、シーズンは C-3a のロールオーバーに乗る)。

## 9. 危険地帯

- duel の二重精算(受諾と失効の競合)と、シーズン切り替えで**全口座**を触ること — どちらも資金に触る。
  別文脈の評価者を通す(`--evaluate every` で回し、最後のタスクも評価させる)。
