# フェーズC-1設計: カジノ経済基盤+スロット

## 背景・目的

3つの取り組み(A: Go移行、B: chosei-sama連携、C: カジノ機能)のうちA・Bは完了済み。
フェーズC(カジノ/賭け事機能)はボリュームが大きいため3段階に分割し、本設計は **C-1** を対象とする。

### フェーズC全体のロードマップ(承認済み)

| 段階 | 内容 | 状態 |
|---|---|---|
| **C-1** | 経済基盤(2層通貨・両替・日次レート・デイリーボーナス)+スロット+簡易ランキング | **本設計の対象** |
| C-2 | メッセージコンポーネント(ボタン)基盤+ハイ&ロー+ブラックジャック | 未設計 |
| C-3 | ジャックポット+宝くじ+/duel(PvP)+シーズン制リーダーボード | 未設計 |

C-2/C-3はC-1完了後にそれぞれ改めてブレインストーミング〜設計を行う。

## 合意済みの基本方針

- **2層通貨制**: 「コイン」(硬貨)はサーバー管理者のみが発行できる。「チップ」(軟貨)は
  デイリーボーナス等でBotが自動配布し、賭けに使う。両者は日次変動レートで両替できる。
- **経済圏はギルド(サーバー)ごとに完全独立**。残高・レート・設定はギルドIDで分離する。
- **毎朝9時(JST)にBotが「本日のレート」を指定チャンネルへ自動掲示する**(プッシュ型の
  デイリーループ)。Botに常駐スケジューラを持たせる。
- 設計の最優先事項は「遊びの面白さ」。読める相場・ニアミス演出・マイルストーン型報酬・
  公開の大勝ち祝いなど、心理設計を仕様に含める(下記)。

## 通貨と経済

- 通貨量はすべて `int64`。**端数は常に切り捨て**、丸め損は常にハウス側の取り分とする
  (丸めで通貨が湧かない・一貫した吸い込み口)。この規則は**通貨量にのみ**適用する。
  レート自体は通貨ではないため四捨五入(→§日次レート)。
- **口座の自動開設**: カジノ系コマンドを初めて使ったユーザーには口座を自動作成し、
  ウェルカムボーナス **1,000チップ** を付与する。コインの初期値は0。
- **両替**(手数料3%、出力側に適用して切り捨て)。二重切り捨てを避けるため、
  int64演算で**最後の除算1回のみ**で切り捨てる形に固定する:
  - コイン→チップ: `chips = (coins × rate × 97) / 100`
  - チップ→コイン: `coins = (chips × 97) / (100 × rate)`
  - 最低両替量: コイン→チップは1コイン以上。チップ→コインは結果が1コイン以上になる量。
- 両替結果の表示には**参謀コメント**を1行添える(例: 「今日のレートは直近7日で2番目の高値です」)。
  相場ゲームは情報が読めてこそ面白い。

## 日次レート(「読める相場」設計)

レートは「1コイン=何チップか」を表す整数。完全ランダムにはせず、判断が意味を持つ相場にする。

- 基準100、範囲 **70〜140** にクランプ。
- **隠れトレンド方式**: レートは内部状態として「強気/弱気/凪」のトレンドを持ち、
  毎日15%の確率で別の状態へ転換する(転換先は他の2状態から等確率)。日次変動は
  `トレンドによるドリフト(強気: +1〜4% / 弱気: -1〜4% / 凪: 0)+ ノイズ(±3%、一様分布)`。
- **暴騰/暴落デー**: 毎日5%の確率でドリフト・ノイズに代えて ±15〜30% の大変動を適用する。
  掲示では🚀/💥で大きく演出する。
- 計算順序: ドリフト+ノイズ(またはイベント変動)→ クランプ → 整数へ**四捨五入**
  (切り捨てだと期待値が毎日約−0.5下方に歪み「凪」が実質弱気になるため。
  通貨量の切り捨て規則はレートには適用しない)。
- クランプで端(70/140)に達した日は、翌日以降のトレンドを中央方向へ強制転換する
  (端への張り付きによる下振れリスクゼロの確定利益化を防ぐ)。
- レートとトレンド状態はギルドごとに独立して保持・遷移する。履歴は直近30日分のみ保持する。

### 毎朝の掲示(9:00 JST)

指定チャンネルに掲示するembedの内容:

1. 今日のレート+前日比(📈▲5.2% のような表示)
2. 直近7日のスパークライン(▁▂▄▆█ 等の文字による簡易チャート)
3. 相場コメント1行(トレンド・イベントに応じた定型文。例: 「コイン強気3日目。天井はどこだ?」)
4. **総資産ランキングTOP3**(総資産=チップ+コイン×当日レート)。コイン保有者は
   レート変動だけで順位が動くため、掲示自体が毎朝の楽しみになる。

## デイリーボーナス(/daily)

- 1ユーザー1日1回(JSTの暦日基準)。基本 **200チップ**。
- **ストリーク**: 連続受け取り日数。1日でも空くと1にリセット。
  ボーナス額 = `200 + 50 × (min(streak, 7) - 1)`(7日目以降は上限500)。
- **大入り袋**: ストリークが7の倍数の日はさらに **+500**。
  線形増より「あと2日で大入り」という節目の引力を優先する。
- 表示は公開メッセージで、🔥×連続日数でストリークを目立たせる。
- 残高0でも受け取れるため、破産救済を兼ねる(専用の救済コマンドは作らない)。

## スロット(/slot)

- 3リール。シンボルはレア度3層: 🍒(高頻度・小当たり)/ 🍋🍇🔔(中)/ 💎7️⃣(激レア・大当たり)。
- **ニアミス演出**: 結果は即時に確定するが、表示はメッセージ編集でリールを1個ずつ
  (約0.8秒間隔で)止める。「7️⃣ 7️⃣ …🍋」という惜しい瞬間が目に見える。
- 🍒2個でベット額返還(=「惜しい」体験の頻度を確保する配当ライン)。
- ベット幅: **10〜1,000チップ**。処理順序は
  **控除→抽選→払い戻しの永続化(ここまで即時に完了)→演出**に固定する。
  演出(メッセージ編集)は表示のみであり、Discord API呼び出しの失敗や演出中のクラッシュは
  払い戻しに一切影響しない。ロックは永続化の間だけ保持し、演出中は保持しない。
- **RTP(還元率)目標: 93%±1%**。配当表の具体的なシンボル重み・配当倍率は、
  計画段階でシード付き100万回スピンの統計テストとともに確定する。
  受け入れ条件にはRTPに加えて**ニアミス頻度**(上位シンボル💎/7️⃣が2個一致して外れる頻度が
  数十スピンに1回程度)を含める — 独立リールで上位シンボルが激レアすぎると
  「惜しい瞬間」自体が発生しなくなるため。
- **公開の大勝ち祝い**: 💎💎💎・7️⃣7️⃣7️⃣が出たら、結果メッセージとは別に@メンション付きで
  派手に祝うメッセージを投稿する。他人の大勝ちが見えることが次のプレイヤーを生む。
- 控除分はC-3でジャックポット原資に接続する前提で配当表を設計する(C-1では積立は行わない)。

## コマンド一覧(7本、従来通り `init()` 自己登録)

| コマンド | 内容 | 表示 |
|---|---|---|
| `/balance` | 自分のコイン・チップ・ストリーク・総資産 | 本人のみ(ephemeral) |
| `/daily` | デイリーボーナス受け取り | 公開 |
| `/rate` | 今日のレート+7日間スパークライン | 公開 |
| `/exchange coin-to-chip <枚数>` / `/exchange chip-to-coin <枚数>` | 両替 | 公開 |
| `/slot <bet>` | スロット | 公開 |
| `/rank` | 総資産TOP10 | 公開 |
| `/casino-admin mint <user> <枚数>` / `/casino-admin channel <#ch>` | コイン発行・掲示チャンネル設定 | 管理者のみ |

- `/casino-admin` は `DefaultMemberPermissions`(Administrator)でDiscord側から見せない+
  実行時にも権限を二重チェックする。
- カジノコマンドは登録時に `Contexts`(`InteractionContextGuild`)でギルド専用と宣言し、
  さらに実行時にも `Interaction.GuildID` が空なら「サーバー内で使用してください」の❌応答とする
  (二重ガード)。
- **コマンド名の一意性検査**: 現行の `Register`(`internal/commands/registry.go`)は
  重複名を検出せず後勝ち/先勝ちが不定になるため、C-1で7コマンド追加するのに合わせて
  `Register` に重複名panic(init時=起動時に即検出)を追加する(既存コードへの小改良)。

## アーキテクチャ

新規パッケージ `internal/casino` に経済ロジックを集約する。フェーズBの設計原則を踏襲し、
discordgoに依存しない純粋ロジックと永続化を分離する。

```
internal/casino/store.go      永続化(sync.Mutex単一ライター、temp file+renameのatomic write)
internal/casino/economy.go    レートのランダムウォーク・両替計算・デイリーボーナス計算(純粋関数)
internal/casino/slot.go       リール・配当表・抽選(乱数源を注入可能にしてテスト決定化)
internal/casino/announce.go   毎朝の定時掲示(常駐goroutine)
internal/commands/*.go        各スラッシュコマンド(balance/daily/rate/exchange/slot/rank/casino_admin)
```

### データ(`data/casino.json` 1ファイル)

```go
type GuildEconomy struct {
    AnnounceChannelID string                  // 毎朝のレート掲示先("" = 未設定)
    Rates             []DailyRate             // 日付+レート+トレンド状態の履歴
    LastAnnounced     string                  // 最後に掲示した日付("2026-07-10")
    Users             map[string]*UserAccount // Discord user ID → 口座
}

type UserAccount struct {
    Coins         int64
    Chips         int64
    LastDailyDate string // JST基準 "2026-07-10"
    StreakDays    int
}
```

- トップレベルはギルドID → `GuildEconomy` のマップ。
- 残高の増減は必ず「ロック内で読み→変更→書き」を1トランザクションで行う
  `Update(func(*Data) error)` パターンとし、同時ベットによる残高競合を構造的に防ぐ。
  フェーズBの `internal/store` と同じミューテックス+atomic write規律。
- **危険地帯(CLAUDE.md 絶対規則3と同格)**: 7コマンドと掲示goroutineは必ず
  `casino.Default()` シングルトン(`sync.Once`)経由で同一ストアインスタンスを共有する。
  各所が独自に `New()` するとミューテックスが分裂して排他が無意味になる。
- `data/casino.json` はフェーズBで追加済みの `.gitignore` の `/data/` に含まれる(追加作業なし)。

### スケジューラと時刻

- 日付境界・9時判定はすべて **JST固定**(`time.FixedZone("JST", 9*3600)`。夏時間なし・
  tzdataファイル不要でWindows/Linux両対応)。
- `cmd/bot/main.go` に**フェーズA以来初めての変更**が入る: セッション接続後に
  掲示スケジューラのgoroutineを起動する1箇所のみ(コマンド登録は従来通り自動探索で無変更)。
- スケジューラは「次の9:00 JSTまでsleep→起床時に全ギルドを処理」方式。処理内容:
  今日のレートが未生成なら生成、掲示チャンネル設定済みかつ今日未掲示なら掲示。
  `main.go` のシグナルcontextを受け取り、シャットダウン時にgoroutineを終了させる。
  掲示の送信失敗(チャンネル削除・権限喪失等)はログして継続し、レート生成には影響させない。
- **レートは絶対に欠損しない**: Bot起動時とカジノ機能への初回アクセス時にも
  「今日のレートがなければその場で生成する」フォールバックを持つ(9時にBotが落ちていても壊れない)。
  このフォールバック生成も必ず `Update(func)` トランザクション内で「確認→生成→保存」を
  原子的に行う(複数コマンドの同時アクセスで二重生成→上書きが起きると、
  片方のレートで両替した直後にレートが変わる経済不整合になるため)。
  掲示は `LastAnnounced` で1日1回に制御する。

## エラーハンドリング

フェーズBと同じ方針: ユーザー向けには統一の日本語❌メッセージ、詳細はログのみ。

- 残高不足: 「❌ チップが足りません(現在: N枚)」
- ベット範囲外: 「❌ ベットは10〜1,000チップです」
- 掲示チャンネル未設定で `/casino-admin channel` 未実行: レート生成は正常動作し、掲示のみスキップ
- 権限なしで `/casino-admin`: 「❌ このコマンドはサーバー管理者のみ使用できます」

## テスト方針(フェーズBの流儀を継承)

- **economy(純粋関数)**: シード付き乱数で多数回遷移させ、レートが70〜140を絶対に
  逸脱しないこと。ストリークの継続/リセット/大入り判定。両替の端数処理
  (往復両替で通貨総量が増えないこと)。
- **slot(純粋関数)**: 乱数源を注入した決定的テスト+シード付き100万回スピンで
  RTPが93%±1%に収まる統計テスト。
- **store**: 並行書き込みテスト(同時ベットで残高が壊れない・更新が失われないこと)。
- **時刻依存ロジック**(日付境界・次回9時の計算)は時計(`now func() time.Time`)を
  注入可能にしてテストする。
- コマンドハンドラは「`Handle()` から純粋関数を切り出してテスト」パターン
  (実Discordをモックしない)。

## スコープ外(C-1では作らない)

- ハイ&ロー・ブラックジャック・ボタン操作(→C-2)
- ジャックポット積立・宝くじ・/duel・シーズン制(→C-3)。ただしスロットの配当表は
  ジャックポット接続を見込んで設計する
- レートへのサーバー損益フィードバック(将来の拡張候補。C-1は隠れトレンドのみ)
- 全サーバー共通経済・ユーザー間送金
