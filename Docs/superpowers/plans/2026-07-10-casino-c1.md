## 1. Goal & 期待される挙動変化

- サーバーごとに独立した2層通貨(コイン=管理者発行/チップ=Bot自動配布)経済が動く。
- 毎日、隠れトレンド方式で「読める」相場(70〜140、四捨五入)が生成され、毎朝9:00 JSTに指定チャンネルへ自動掲示される。
- ユーザーは `/balance` `/daily` `/rate` `/exchange` `/slot` `/rank` を使え、サーバー管理者は `/casino-admin` でコイン発行・掲示チャンネル設定ができる。
- `/slot` はRTP93%±1%・ニアミス演出(リールを1個ずつ約0.8秒間隔で止める)・💎💎💎/7️⃣7️⃣7️⃣の公開祝いを持つ。
- Bot起動後、ダウンタイムがあっても「レートが存在しない日」は発生しない(フォールバック生成)。
- `internal/commands.Register` が同名コマンドの二重登録を起動時にpanicで検出するようになる(既存8+新規7=15コマンドの名前衝突を機械的に防止)。

### 3.3 Store の骨格(単一ライター規律 — `internal/store/events.go` を踏襲)

```go
const DefaultPath = "data/casino.json"

// randSource is the minimal randomness surface economy.go and slot.go need
// injected for deterministic tests (see §3.4 correction below).
type Store struct {
    mu   sync.Mutex
    path string
    rng  randSource // production: rand.New(rand.NewSource(time.Now().UnixNano())); accessed only while mu is held (inside Update)
}

func New(path string) *Store { return &Store{path: path, rng: rand.New(rand.NewSource(time.Now().UnixNano()))} }

var (
    defaultOnce  sync.Once
    defaultStore *Store
)

func Default() *Store {
    defaultOnce.Do(func() { defaultStore = New(DefaultPath) })
    return defaultStore
}

// Update runs fn against the current on-disk Data under the store's single
// writer lock, and atomically persists fn's mutations if fn returns nil (a
// non-nil error aborts the write — the file is left untouched). This is
// the ONLY way production code may mutate casino data; every balance
// change, rate generation, or admin mint must go through Update so
// concurrent commands (e.g. two simultaneous /slot bets in the same guild)
// serialize correctly — mirrors internal/store.Store's mutex discipline.
func (s *Store) Update(fn func(*Data) error) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    data, err := s.readLocked()
    if err != nil { return err }
    if err := fn(&data); err != nil { return err }
    return s.writeLocked(data)
}

// Read runs fn against a read-only snapshot of the current on-disk Data,
// under the same lock (so it cannot race a concurrent Update's
// read-modify-write), but never writes back — for display-only paths
// that don't need a mutating helper.
func (s *Store) Read(fn func(Data) error) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    data, err := s.readLocked()
    if err != nil { return err }
    return fn(data)
}

// readLocked / writeLocked: same shape as internal/store/events.go's
// readLocked/writeLocked (temp file in the same dir + os.Rename for atomic
// write; missing file => empty, non-nil Data{} — NOT an error). Temp-file
// glob: ".casino-*.json.tmp" (events.go uses ".chosei-events-*.json.tmp" —
// same convention, different prefix so the two stores' temp files are
// visually distinguishable in a shared data/ directory during debugging).
```

**危険地帯(CLAUDE.md 絶対規則3と同格、設計書の同規律)**: 7コマンド + 掲示スケジューラは必ず `casino.Default()` を経由して同一の `*Store`(=同一の `sync.Mutex`)を共有すること。`casino.New(path)` は**テストコードでの `t.TempDir()` 使用専用**(`internal/store` と全く同じ規約)。この規律はTask 18(architecture.md更新)で文書化する。

### 3.4 エラー方針(既存コードの精査から導いた修正)

`internal/store/events.go` を確認した結果、**日本語ユーザー向け文言は常に `internal/commands` 層だけが持つ**という一貫した規約を発見した(`internal/store` は英語のエラーのみを返し、日本語❌文言は `schedule.go`/`schedule_result.go`/`reminder.go` の中で組み立てられている。`reminder.go` の `errors.As(err, &apiErr)` によるAPI固有エラーの判定パターンが好例)。

この規約に従い、**`internal/casino` は構造化されたセンチネル/カスタムエラー型のみを返し、日本語❌文言は一切持たない**。`internal/commands/*.go` が `errors.Is`/`errors.As` で判定し、日本語文言に翻訳する。設計書の「エラーハンドリング」節の4つの❌文言は、**この翻訳後の最終文字列としてコマンド層で使う**(既存の慣習と整合)。

```go
var (
    ErrAlreadyClaimedToday  = errors.New("casino: daily bonus already claimed today")
    ErrBetOutOfRange        = errors.New("casino: bet out of range")
    ErrInvalidAmount        = errors.New("casino: amount must be a positive integer")
    ErrBelowMinimumExchange = errors.New("casino: exchange result would be below the 1-coin minimum")
    ErrAmountOverflow       = errors.New("casino: amount would overflow int64")
)

// ErrInsufficientChips carries the current balance so the command layer can
// render "❌ チップが足りません(現在: N枚)" without a second store round-trip.
type ErrInsufficientChips struct{ Balance int64 }
func (e *ErrInsufficientChips) Error() string { return fmt.Sprintf("casino: insufficient chips (balance=%d)", e.Balance) }

// ErrInsufficientCoins mirrors ErrInsufficientChips for coin→chip exchange.
type ErrInsufficientCoins struct{ Balance int64 }
func (e *ErrInsufficientCoins) Error() string { return fmt.Sprintf("casino: insufficient coins (balance=%d)", e.Balance) }
```

いずれも**日本語文言を持たない**。`ExchangeCoinToChip`/`Mint` の「入力量は1以上」チェックには `ErrInvalidAmount` を、`ExchangeChipToCoin` の「**計算結果**が1コイン未満」チェックには `ErrBelowMinimumExchange` を使い分ける(設計書: コイン→チップは入力側の最低量、チップ→コインは結果側の最低量 — チェック対象が異なるので別センチネルにする)。

**Part 1からの訂正**: `Store.rng` のフィールド型は具象型 `*rand.Rand` ではなく **`randSource` インターフェース型**にする。テストで「常に固定値を返すスタブ」を注入して `Spin`/`EnsureTodayRate` 等の分岐を決定的に検証するため(`*rand.Rand` は `randSource`(`Float64() float64`, `Intn(n int) int`)を構造的に満たすので、production の `New()`/`Default()` は引き続き `rand.New(rand.NewSource(time.Now().UnixNano()))` を設定するだけで済み、挙動は変わらない)。

### 3-A. `randSource` インターフェースと `nextRate`

```go
// randSource is the minimal randomness surface economy.go and slot.go need
// injected for deterministic tests. *rand.Rand (via rand.New) satisfies it
// structurally; production code always constructs a real *rand.Rand (never
// uses the global math/rand top-level functions, for reproducibility).
type randSource interface {
	Float64() float64
	Intn(n int) int
}

const (
	baseRate            = 100
	minRate             = 70
	maxRate             = 140
	trendTransitionProb = 0.15
	eventProb           = 0.05
)

// nextRate computes tomorrow's rate and trend from today's rate/trend,
// using rng for all randomness. Pure — no I/O, no locking, no wall-clock
// reads. hasPrev=false means "this guild's very first day": returns
// exactly (baseRate, TrendFlat) with NO randomness consumed (day 1 is a
// fixed starting point per 設計書 "基準100", not a random draw — a
// disclosed interpretation since the design doc doesn't state day-1
// behavior explicitly).
//
// Precedence when hasPrev is true (disclosed interpretation of 設計書,
// which doesn't spell out interaction with the 15% roll): a boundary-forced
// transition REPLACES the 15% roll for that day (not "both apply") — if
// prevRate is at the 70/140 clamp, the trend is forced toward the center
// and the independent 15% transition check is skipped entirely for this
// call.
func nextRate(prevRate int, prevTrend TrendState, hasPrev bool, rng randSource) (rate int, trend TrendState) {
	if !hasPrev {
		return baseRate, TrendFlat
	}

	trend = prevTrend
	switch {
	case prevRate <= minRate:
		trend = TrendBull
	case prevRate >= maxRate:
		trend = TrendBear
	case rng.Float64() < trendTransitionProb:
		trend = otherTrend(prevTrend, rng)
	}

	var pct float64
	if rng.Float64() < eventProb {
		magnitude := 15 + rng.Float64()*15 // 15..30
		if rng.Float64() < 0.5 {
			pct = magnitude
		} else {
			pct = -magnitude
		}
	} else {
		var drift float64
		switch trend {
		case TrendBull:
			drift = 1 + rng.Float64()*3 // 1..4
		case TrendBear:
			drift = -(1 + rng.Float64()*3) // -1..-4
		case TrendFlat:
			drift = 0
		}
		noise := -3 + rng.Float64()*6 // -3..3
		pct = drift + noise
	}

	raw := float64(prevRate) * (1 + pct/100)
	clamped := math.Max(minRate, math.Min(maxRate, raw))
	return int(math.Round(clamped)), trend // math.Round = 四捨五入(半分は0から遠い方へ), never floor
}

func otherTrend(current TrendState, rng randSource) TrendState {
	candidates := make([]TrendState, 0, 2)
	for _, t := range []TrendState{TrendBull, TrendBear, TrendFlat} {
		if t != current {
			candidates = append(candidates, t)
		}
	}
	return candidates[rng.Intn(len(candidates))]
}
```

### 4-A. 確定した配当表(このプランで数値的に導出・検証済み)

**導出方法**: `fractions.Fraction`(Python標準ライブラリ)による厳密分数演算で全27通りの3リール組み合わせを列挙し、期待値(RTP)とニアミス確率を**厳密値**として算出した。さらに実際の `math/rand`(Go, v1 API — 本プロジェクトが `dice.go` で使っているのと同じパッケージ)で5つの異なるシード×100万回スピンを実行し、解析値と実測値が一致することを確認した。

| symbol | 絵文字 | 重み(/100) | 3個揃い倍率 |
|---|---|---|---|
| cherry | 🍒 | 28 | ×7 |
| lemon | 🍋 | 22 | ×16 |
| grape | 🍇 | 21 | ×22 |
| bell | 🔔 | 18 | ×32 |
| diamond | 💎 | 7 | ×98 |
| seven | 7️⃣ | 4 | ×196 |

追加ルール: 🍒がちょうど2個(3個目は別シンボル)→ ベット額返還(倍率×1)。

**重み・倍率とも頻度順に単調**(cherry最頻出/最低倍率 → seven最希少/最高倍率)であり、設計書の「🍒(高頻度・小当たり)/🍋🍇🔔(中)/💎7️⃣(激レア・大当たり)」という3層構造と整合する(探索の過程で「cherryの倍率がlemon/grapeより高くなってしまう」候補を複数リジェクトした上でこの表に確定した)。

**解析的な厳密値**(分数演算、丸め誤差なし):
- RTP(期待倍率) = 9299/10000 = **92.99%**(目標93%±1%の帯の中央付近)
- ニアミス(💎または7️⃣がちょうど2個一致、3個目は別) 確率 = **1/54.71**(「数十スピンに1回程度」の目標を満たす)
- 🍒2個返還 確率 = **1/5.91**

**実測値**(Go `math/rand`, 100万スピン/シード、ベット=100):

| seed | RTP | ニアミス頻度 |
|---|---|---|
| 1 | 0.93079 | 1-in-55.2 |
| 2 | 0.92539 | 1-in-54.3 |
| 42 | 0.92424 | 1-in-54.7 |
| 12345 | 0.92148 | 1-in-54.2 |
| 999 | 0.92293 | 1-in-54.7 |

全シードが `[0.92, 0.94]` の帯に収まり、解析値(92.99%, 1-in-54.71)と高い精度で一致した。**統計テストには `seed=1` を使うことを推奨する**(RTP=0.93079で目標93%に最も近く、帯の中心から余裕がある)。

**統計的な健全性の根拠**(RTP推定量の理論標準偏差): 分散 `Var(X)≈19.31`(1スピンあたりの倍率の分散)から、100万スピンの平均RTP推定量の標準誤差は約0.44パーセントポイント。したがって固定シードでの単発テストが偶然帯域外に出る確率は無視できないゼロではないが(3σで約±1.3pt)、上記5シードすべてが安全に収まっていることを実測で確認済みなので、`seed=1` を採用すれば実装時に再度シード探しをする必要はない。

```go
type SlotSymbol string

const (
	SymbolCherry  SlotSymbol = "🍒"
	SymbolLemon   SlotSymbol = "🍋"
	SymbolGrape   SlotSymbol = "🍇"
	SymbolBell    SlotSymbol = "🔔"

// reelWeights is the fixed draw order for the cumulative-distribution
// lookup in drawSymbol. MUST be a slice, not a map iterated directly — Go
// randomizes map iteration order, which would make Spin's output
// non-deterministic for a given rng sequence even with a seeded source.
// Sum of Weight == 100 (verified: 28+22+21+18+7+4=100).
var reelWeights = []struct {
	Symbol SlotSymbol
	Weight int
}{
	{SymbolCherry, 28}, {SymbolLemon, 22}, {SymbolGrape, 21},
	{SymbolBell, 18}, {SymbolDiamond, 7}, {SymbolSeven, 4},
}

var triplePayout = map[SlotSymbol]int64{
	SymbolCherry: 7, SymbolLemon: 16, SymbolGrape: 22,
	SymbolBell: 32, SymbolDiamond: 98, SymbolSeven: 196,
}

const cherryPairPayout int64 = 1 // "🍒2個でベット額返還"

// SpinResult is Spin's outcome — exported because internal/commands/slot.go
// (a different package) renders it into the Discord response.
type SpinResult struct {
	Reels     [3]SlotSymbol
	Bet       int64
	Payout    int64 // total chips credited back; 0 on a loss
	IsJackpot bool  // true iff Reels is 💎💎💎 or 7️⃣7️⃣7️⃣ — triggers the public celebration message
}

func drawSymbol(rng randSource) SlotSymbol {
	n := rng.Intn(100)
	acc := 0
	for _, e := range reelWeights {
		acc += e.Weight
		if n < acc {
			return e.Symbol
		}
	}
	return reelWeights[len(reelWeights)-1].Symbol // unreachable: weights sum to 100
}

// spin draws 3 independent reels and resolves the payout. Pure — bet is
// NOT deducted or credited here (that's Store.Spin's job, inside a locked
// Update transaction — see Task 5).
func spin(bet int64, rng randSource) SpinResult {
	reels := [3]SlotSymbol{drawSymbol(rng), drawSymbol(rng), drawSymbol(rng)}
	return SpinResult{
		Reels:     reels,
		Bet:       bet,
		Payout:    payoutFor(reels, bet),
		IsJackpot: reels == [3]SlotSymbol{SymbolDiamond, SymbolDiamond, SymbolDiamond} || reels == [3]SlotSymbol{SymbolSeven, SymbolSeven, SymbolSeven},
	}
}

func payoutFor(reels [3]SlotSymbol, bet int64) int64 {
	if reels[0] == reels[1] && reels[1] == reels[2] {
		return bet * triplePayout[reels[0]]
	}
	cherryCount := 0
	for _, r := range reels {
		if r == SymbolCherry {
			cherryCount++
		}
	}
	if cherryCount == 2 {
		return bet * cherryPairPayout
	}
	return 0
}
```

### 5-C. ⚠️ 重要な正しさの注意点(実装者が絶対に踏んではいけない罠)

`Store.mu` は **再入不可**(Goの`sync.Mutex`の標準的な性質)。したがって「`Update` の中から `s.Update` を呼ぶ」ことは**デッドロックする**。しかし `ExchangeCoinToChip`/`ExchangeChipToCoin`/`TopAssets`/`ViewAccount`/`collectDailyAnnouncements`(Task 6)はいずれも「同じトランザクション内で"今日のレートを保証してから残高を触る"」ことが必須(そうしないと、レート確認とチップ操作の間に別goroutineが割り込んでレートを変えてしまい得る=経済不整合)。

このため **`EnsureTodayRate`(公開・独自にロックを取る)と、ロック取得済み文脈でだけ呼べる `ensureTodayRateLocked`(非公開・ロックを取らない)を分離する**:

```go
// EnsureTodayRate makes sure guildID has a DailyRate for today's JST
// calendar date, generating one via a random-walk step if missing. Public
// entry point — takes the lock itself. Do NOT call this from inside
// another Update closure (deadlock) — internal callers that need "today's
// rate" as part of their own transaction must call ensureTodayRateLocked
// directly instead (see ExchangeCoinToChip/ExchangeChipToCoin/TopAssets/
// ViewAccount below, and collectDailyAnnouncements in Task 6).
func (s *Store) EnsureTodayRate(guildID string, now time.Time) (DailyRate, error) {
	today := jstDate(now)
	var result DailyRate
	err := s.Update(func(d *Data) error {
		economy := ensureGuildLocked(d, guildID)
		result = ensureTodayRateLocked(economy, today, s.rng)
		return nil
	})
	return result, err
}

// ensureTodayRateLocked returns economy's DailyRate for `today`, appending
// a freshly-generated one (via nextRate, Task 3) if missing, and trimming
// history to the most recent 30 entries (設計書). Caller must already
// hold the Store's lock.
func ensureTodayRateLocked(economy *GuildEconomy, today string, rng randSource) DailyRate {
	if n := len(economy.Rates); n > 0 && economy.Rates[n-1].Date == today {
		return economy.Rates[n-1]
	}
	var prevRate int
	var prevTrend TrendState
	hasPrev := len(economy.Rates) > 0
	if hasPrev {
		last := economy.Rates[len(economy.Rates)-1]
		prevRate, prevTrend = last.Rate, last.Trend
	}
	rate, trend := nextRate(prevRate, prevTrend, hasPrev, rng)
	result := DailyRate{Date: today, Rate: rate, Trend: trend}
	economy.Rates = append(economy.Rates, result)
	if len(economy.Rates) > 30 {
		economy.Rates = economy.Rates[len(economy.Rates)-30:]
	}
	return result
}
```

```go
// topAssetsLocked ranks economy's users by total assets at `rate`, ties
// broken by ascending UserID for deterministic output. Caller must already
// hold the Store's lock.
func topAssetsLocked(economy *GuildEconomy, rate int, limit int) []RankEntry {
	entries := make([]RankEntry, 0, len(economy.Users))
	for userID, account := range economy.Users {
		entries = append(entries, RankEntry{UserID: userID, TotalAssets: account.Chips + account.Coins*int64(rate)})

			return entries[i].TotalAssets > entries[j].TotalAssets
		}
		return entries[i].UserID < entries[j].UserID
	})
	if len(entries) > limit {
		entries = entries[:limit]
	}
	return entries
}
```

```go
// rate (ensured in the same transaction). Minimum: coins >= 1.
func (s *Store) ExchangeCoinToChip(guildID, userID string, coins int64, now time.Time) (ExchangeResult, error) {

		return ExchangeResult{}, ErrInvalidAmount

	today := jstDate(now)
	var result ExchangeResult

		economy := ensureGuildLocked(d, guildID)

		}

		account.Chips += chips

	})

// checked after computing the exchange.

		return ExchangeResult{}, ErrInvalidAmount
	}
	today := jstDate(now)
	var result ExchangeResult
	err := s.Update(func(d *Data) error {

		account := ensureAccountLocked(economy, userID)

			return &ErrInsufficientChips{Balance: account.Chips}

			return err

			return ErrBelowMinimumExchange

		account.Coins += coins
		result = ExchangeResult{Spent: chips, Received: coins, RateUsed: rate.Rate}
		return nil
	})
```

```go
// with an AnnounceChannelID configured that has not yet been announced
// today (LastAnnounced != today; 設計書). Does NOT mark LastAnnounced (only
// MarkAnnounced does, after a confirmed send) and does NOT send anything.
func (s *Store) collectDailyAnnouncements(now time.Time) ([]AnnouncementJob, error) {

// tomorrow's 9am wake naturally retries (設計書: 送信失敗はログして継続).
func (s *Store) MarkAnnounced(guildID, date string) error {
	return s.Update(func(d *Data) error {
		ensureGuildLocked(d, guildID).LastAnnounced = date
		return nil
	})

// nextRunAt returns the next 9:00 JST instant strictly after now (an input
// exactly at 9:00:00.000 JST rolls to the FOLLOWING day — a deliberate
// simplification avoiding a double-fire race right at the boundary).
func nextRunAt(now time.Time) time.Time {
	j := now.In(jst)
	next := time.Date(j.Year(), j.Month(), j.Day(), 9, 0, 0, 0, jst)
	if !next.After(j) {
		next = next.AddDate(0, 0, 1)
	}
	return next
}

// AnnounceCallback is invoked once per pending job by RunAnnounceScheduler.
// Returning nil means "sent successfully" (triggers MarkAnnounced); a
// non-nil error is logged here and left for tomorrow's retry.
type AnnounceCallback func(job AnnouncementJob) error

// sleepFunc blocks until `until` or ctx cancellation, returning false if
// ctx was cancelled (caller should stop) or true if it woke at `until`.
type sleepFunc func(ctx context.Context, until time.Time) bool

// RealSleepUntil is the production sleepFunc — a real, cancellable timer
// wait. Exported so internal/commands/casino_announce.go can pass it.
func RealSleepUntil(ctx context.Context, until time.Time) bool {
	timer := time.NewTimer(time.Until(until))
	defer timer.Stop()
	select {
	case <-ctx.Done():
		return false
	case <-timer.C:
		return true
	}
}

// RunAnnounceScheduler blocks until ctx is cancelled, waking every 9:00
// JST (computed via now, injected for tests) to ensure every known
// guild's rate exists and invoke callback for each pending announcement,
// marking successfully-sent ones via MarkAnnounced. now/sleep are injected
// so tests never block on a real clock.
func RunAnnounceScheduler(ctx context.Context, st *Store, callback AnnounceCallback, now func() time.Time, sleep sleepFunc) {
	for {
		if !sleep(ctx, nextRunAt(now())) {
			return
		}
		jobs, err := st.collectDailyAnnouncements(now())
		if err != nil {
			slog.Error("casino: collectDailyAnnouncements failed", "error", err)
			continue
		}
		for _, job := range jobs {
			if err := callback(job); err != nil {
				slog.Error("casino: announcement callback failed", "guild_id", job.GuildID, "error", err)
				continue
			}
			if err := st.MarkAnnounced(job.GuildID, job.Today.Date); err != nil {
				slog.Error("casino: MarkAnnounced failed", "guild_id", job.GuildID, "error", err)
			}
		}
	}
}
```

```go
// sparkline renders values (oldest..newest rate integers) as a block-chart
// string (設計書). Each value is bucketed into 8 levels by its
// position within [min(values), max(values)]; a flat series renders the
// lowest bar for every point.
func sparkline(values []int) string {
	if len(values) == 0 {
		return ""
	}
	lo, hi := values[0], values[0]
	for _, v := range values {
		if v < lo {
			lo = v
		}
		if v > hi {
			hi = v
		}
	}
	span := hi - lo
	var b strings.Builder
	for _, v := range values {
		idx := 0
		if span > 0 {
			idx = (v - lo) * (len(sparkChars) - 1) / span
		}
		b.WriteRune(sparkChars[idx])
	}
	return b.String()
}
```

```go
type SlotCommand struct{ store *casino.Store }

func (c *SlotCommand) Definition() *discordgo.ApplicationCommand {

// slotResponder abstracts the *discordgo.Session methods the reveal
// animation needs, so runReveal can be unit tested without a real Discord
// connection. *discordgo.Session satisfies this structurally (same pattern
// as reminder.go's discordWebhookCreator).
type slotResponder interface {
	InteractionRespond(interaction *discordgo.Interaction, resp *discordgo.InteractionResponse, options ...discordgo.RequestOption) error
	InteractionResponseEdit(interaction *discordgo.Interaction, newresp *discordgo.WebhookEdit, options ...discordgo.RequestOption) (*discordgo.Message, error)
	ChannelMessageSend(channelID, content string, options ...discordgo.RequestOption) (*discordgo.Message, error)
}

const slotRevealPlaceholder = "❔"

// buildSlotRevealStages returns the 4 progressive message bodies for the
// "リールを1個ずつ止める" animation (設計書): stage 0 = all ❔, stages
// 1-3 reveal one more reel each; stage 3 also appends the payout line.
func buildSlotRevealStages(result casino.SpinResult) []string {
	reelText := func(revealed int) string {
		cells := make([]string, 3)
		for i := 0; i < 3; i++ {
			if i < revealed {
				cells[i] = string(result.Reels[i])
			} else {
				cells[i] = slotRevealPlaceholder
			}
		}
		return strings.Join(cells, " ")
	}
	stages := make([]string, 4)
	for revealed := 0; revealed <= 3; revealed++ {
		line := fmt.Sprintf("🎰 %s", reelText(revealed))
		if revealed == 3 {
			line += "\n" + slotResultLine(result)
		}
		stages[revealed] = line
	}
	return stages
}

func slotResultLine(result casino.SpinResult) string {
	if result.Payout > 0 {
		return fmt.Sprintf("🎉 %d枚 獲得!(ベット%d枚)", result.Payout, result.Bet)
	}
	return fmt.Sprintf("😢 ハズレ(ベット%d枚)", result.Bet)
}

func translateSlotError(err error) string {
	var insufficientChips *casino.ErrInsufficientChips
	switch {
	case errors.As(err, &insufficientChips):
		return fmt.Sprintf("❌ チップが足りません(現在: %d枚)", insufficientChips.Balance)
	case errors.Is(err, casino.ErrBetOutOfRange):
		return "❌ ベットは10〜1,000チップです" // 設計書と完全一致させる
	default:
		slog.Error("casino: spin failed", "error", err)
		return "❌ スロットの実行に失敗しました。"
	}
}

// runReveal performs the reel-by-reel animation via InteractionRespond +
// InteractionResponseEdit at ~800ms intervals (設計書), and — if
// result.IsJackpot — posts a SEPARATE public celebration message
// @mentioning userID (設計書). result's balances are ALREADY
// persisted by the time this runs (c.store.Spin, called from Handle,
// already completed) — a Discord API failure or crash here cannot affect
// balances or duplicate/roll back the payout (設計書:
// 「演出中のクラッシュは払い戻しに一切影響しない」). sleep is injected
// (production: time.Sleep) so tests don't take ~2.4s of real wall-clock
// time. Blocking here for ~2.4s is safe: discordgo dispatches each
// InteractionCreate handler in its own goroutine, so this does not
// stall the gateway read loop or other concurrent interactions.
func (c *SlotCommand) runReveal(responder slotResponder, interaction *discordgo.Interaction, channelID, userID string, result casino.SpinResult, sleep func(time.Duration)) error {
	stages := buildSlotRevealStages(result)

	if err := responder.InteractionRespond(interaction, &discordgo.InteractionResponse{
		Type: discordgo.InteractionResponseChannelMessageWithSource,
		Data: &discordgo.InteractionResponseData{Content: stages[0]},
	}); err != nil {
		return err
	}

	for _, stage := range stages[1:] {
		sleep(800 * time.Millisecond)
		content := stage
		if _, err := responder.InteractionResponseEdit(interaction, &discordgo.WebhookEdit{Content: &content}); err != nil {
			slog.Error("discord: InteractionResponseEdit failed during slot reveal", "error", err)
			return nil // 演出の失敗は払い戻しに一切影響しない(設計書)。ログのみ、呼び出し元にはエラーを伝播しない。
		}
	}

	if result.IsJackpot {
		celebration := fmt.Sprintf("🎉🎉🎉 <@%s> が %s%s%s で大当たり!! 🎉🎉🎉", userID, result.Reels[0], result.Reels[1], result.Reels[2])
		if _, err := responder.ChannelMessageSend(channelID, celebration); err != nil {
			slog.Error("discord: ChannelMessageSend failed for jackpot celebration", "error", err)
		}
	}
	return nil
}

func (c *SlotCommand) Handle(s *discordgo.Session, i *discordgo.InteractionCreate) error {
	if msg := requireGuildContext(i); msg != "" {
		return s.InteractionRespond(i.Interaction, &discordgo.InteractionResponse{
			Type: discordgo.InteractionResponseChannelMessageWithSource,
			Data: &discordgo.InteractionResponseData{Content: msg},
		})
	}

	var bet int64
	for _, opt := range i.ApplicationCommandData().Options {
		if opt.Name == "bet" {
			bet = opt.IntValue()
		}
	}
	if bet < 10 || bet > 1000 { // defense in depth — Discord's MinValue/MaxValue already enforce this client-side
		return s.InteractionRespond(i.Interaction, &discordgo.InteractionResponse{
			Type: discordgo.InteractionResponseChannelMessageWithSource,
			Data: &discordgo.InteractionResponseData{Content: "❌ ベットは10〜1,000チップです"},
		})
	}

	userID := resolveUserID(i)
	result, err := c.store.Spin(i.GuildID, userID, bet)
	if err != nil {
		return s.InteractionRespond(i.Interaction, &discordgo.InteractionResponse{
			Type: discordgo.InteractionResponseChannelMessageWithSource,
			Data: &discordgo.InteractionResponseData{Content: translateSlotError(err)},
		})
	}

	return c.runReveal(s, i.Interaction, i.ChannelID, userID, result, time.Sleep)
}
```

```go
// buildAnnouncementEmbed renders one AnnouncementJob into the 9am posting
// (設計書: レート+前日比、7日間スパークライン、参謀コメント、総資産TOP3).
// 🚀/💥 のしきい値10%は、通常デーの最大変動(drift最大4%+noise最大3%=7%)と
// 暴騰/暴落デー(15〜30%)の間に安全に収まる値として選んだ(設計書はEvent専用
// フィールドの保持を要求していないため、前日比%から導出する — §3.1の判断)。
func buildAnnouncementEmbed(job casino.AnnouncementJob) *discordgo.MessageEmbed {
	values := make([]int, len(job.RecentRates))
	for i, r := range job.RecentRates {
		values[i] = r.Rate
	}

	changeLine := "本日が最初の記録です。"
	if len(job.RecentRates) >= 2 {
		prev := job.RecentRates[len(job.RecentRates)-2].Rate
		diff := job.Today.Rate - prev
		pct := float64(diff) / float64(prev) * 100
		arrow := "📈▲"
		if diff < 0 {
			arrow = "📉▼"
		}
		eventTag := ""
		if pct >= 10 {
			eventTag = "🚀"
		} else if pct <= -10 {
			eventTag = "💥"
		}
		changeLine = fmt.Sprintf("%s%s%.1f%%(前日比 %+d)", eventTag, arrow, pct, diff)
	}

	rankLines := make([]string, 0, len(job.TopAssets))
	for i, e := range job.TopAssets {
		marker := fmt.Sprintf("%d.", i+1)
		if i < len(announceMedals) {
			marker = announceMedals[i]
		}
		rankLines = append(rankLines, fmt.Sprintf("%s <@%s> — %d", marker, e.UserID, e.TotalAssets))
	}
	rankValue := "まだ誰も口座を持っていません。"
	if len(rankLines) > 0 {
		rankValue = strings.Join(rankLines, "\n")
	}

	return &discordgo.MessageEmbed{
		Title:       "💱 本日のコインレート",
		Description: fmt.Sprintf("1コイン = %dチップ\n%s\n直近%d日: %s", job.Today.Rate, changeLine, len(job.RecentRates), sparkline(values)),
		Color:       0xf1c40f,
		Fields: []*discordgo.MessageEmbedField{
			{Name: "総資産ランキング TOP3", Value: rankValue, Inline: false},
		},
	}
}
```

## リスクレベル

`Docs/agent-guide/orchestration.md` の「昇格条件(高リスク領域)」および `architecture.md` の既存「危険地帯」パターンと突き合わせると、本フェーズは以下が該当する:

1. **`internal/commands/registry.go`(Task 1)と `cmd/bot/main.go`(Task 17)** — orchestration.md「`commands.Command`契約・自己登録レジストリ・`cmd/bot/main.go`のディスパッチ配線 — 全コマンドに波及する」に**文字通り該当**。特にTask 1の変更は既存8コマンド全ての起動可否に影響し得る(重複名判定のロジックにバグがあれば、無関係な既存コマンドの起動が壊れる)。
   - **封じ込め策**: Task 1は独立した最小のコミット(Commit A)とし、他の変更と混ぜない。テストは新規追加分だけでなく`TestRegisterAndAll`(既存)も必ず再実行して既存動作に影響がないことを確認する。
2. **`internal/casino.Store` の単一ライター規律(Task 2, 5〜7)** — `internal/store`と同格の危険地帯(architecture.md 危険地帯4点目、Task 18で追記)。**加えて本フェーズ固有の新しいリスク**として、`Update`クロージャ内から再度ロックを取るとデッドロックする構造(`ensureTodayRateLocked`等の`*Locked`ヘルパー分離)がある — この分離を実装者が誤って崩す(=`s.Update`をクロージャ内から呼んでしまう)と、本番で特定の操作(両替・スロット・ランキング表示)がハングする重大障害になり得るが、**ローカルの単体テストでは検出しにくい**(デッドロックはテストがタイムアウトするまで気づかれない可能性がある)。
   - **封じ込め策**: 実装レビューで`*Locked`ヘルパーの呼び出し元をすべて確認し、`s.Update`/`s.EnsureTodayRate`等ロックを取る公開メソッドが他の公開メソッドの`Update`クロージャ内から呼ばれていないことを目視+`grep`で機械的に確認する(例: `grep -n "s\.Update\|s\.EnsureTodayRate\|s\.TopAssets\|s\.RecentRates" internal/casino/*.go` でクロージャ内呼び出しがないか洗う)。`go test ./...`のデフォルトタイムアウト(パッケージあたり10分)により、デッドロックがあれば少なくとも検証時にハングという形で顕在化する(サイレントに見逃されることはない)。
3. **`/casino-admin`の権限ガード(Task 15)** — 明示的な危険地帯リストには無いが、**任意のコインを無制限に発行できる管理者専用コマンド**であり、権限チェックの不備は経済の完全性を破壊する。`DefaultMemberPermissions`(Discord UI側)と`requireAdministrator`(実行時)の二重ガードは設計書の要求どおりだが、**実装レビューでこの2つが両方とも実際にDefinition()/Handle()に存在し、どちらか一方だけになっていないことを重点確認する**。
   - **封じ込め策**: `TestCasinoAdminCommand_Definition_HasAdministratorPermissionAndGuildContext`(Definition側)と`TestBuildResponse_NonAdministrator_ReturnsExactDesignMessage`(実行時側)の両方が独立してレビューで確認されること。
4. **スロットの配当表(Task 4)の数値的正しさ** — 経済的に大きな影響(RTPが計算間違いで93%を大きく外れると、長期的にBotの通貨経済が壊れるか、あるいは即座に破綻するほど気前が良すぎる)。本計画では厳密分数演算+実測(Go `math/rand`5シード)で二重検証済みだが、**実装レビューでこの計画に書かれた重み・倍率の表がそのまま`internal/casino/slot.go`に転記されているか(実装者が「もっともらしい」別の数値に変えていないか)を数値レベルで突き合わせて確認すること**を推奨する。

**ロールバック/封じ込め戦略**: Commit A〜Dは各々独立してrevert可能な単位にする(Commit B〜Dはそれぞれ内部で`go build`/`go test`が通る状態を保つ)。万が一本番投入後に経済的な不整合(残高のロスト更新・レート異常等)が発覚した場合は、`data/casino.json`はgitignore対象の実行時生成物なので**ファイルを削除して再生成すれば経済状態はリセットできる**(設計書のフォールバック機構により、次回アクセス時に口座・レートが自動再生成される)。ユーザーには実質的な補填は無いが、Bot自体は自己修復する — 秘密情報の漏洩のような取り返しのつかない被害ではない。
