## 2. 「所有権と寿命」— 日次ロールオーバーで動くもの

次の段落を `internal/casino.DefaultSessions()` の段落の**前**(= `casino.Default()` の段落の後ろ)に足す:

- **日次ロールオーバーは `ensureTodayRateIndexLocked` 1 箇所**で、そこで動くのは次の 3 つ。すべて呼び出し側の `Update` の内側、
  つまり 1 回の書き込みで一緒にコミットされる(レートだけ新しくて宝くじが前日のまま、という中間状態は保存されない):
  1. **今日のレートの生成**(`ensureTodayRateLocked`。JST の**深夜**で切り替わる)。
  2. **ジャックポットの種**(`seedJackpotLocked`。C-3a 以前の `data/casino.json` はプール 0 で読み込まれるので、
     読み取り経路で 1,000 チップへ引き上げる。`/balance`・`/rank`・`/rate`・9 時掲示が通る唯一の場所なので、
     まだ誰もスピンしていないギルドにも効く)。
  3. **宝くじの抽選**(`drawLotteryLocked`。JST の **09:00** で切り替わる)。
- レートは深夜・抽選は 9 時なので、**同じ `now` から 2 つの日付を作る**(`jstDate` と `lotteryDrawDate`)。
  片方だけにすると、9 時前に買った券が前夜のうちに抽選されるか、抽選済みの回に券が混ざる。
- 抽選をここに置いたのは 9 時掲示スケジューラに置かないためで、理由は 2 つ:
  掲示チャンネル未設定のギルドで抽選が黙って飛ぶ / 9 時に Bot が落ちているとその日が丸ごと消える。
  ここなら起動後の最初のコマンドでも抽選され、結果は `LastDraw` に残る(`/lottery status` で見える)。
- 日付の比較は `DrawDate < today`(`!=` ではない)。時計が巻き戻っても支払い済みの回を引き直さない。

## 3. 「危険地帯」6 点目

冒頭の「危険地帯は以下の5点」を「6点(フェーズAの2点に、B・C-1・C-2・C-3aで1点ずつ追加)」に直し、次を 6 番目として足す:

6. **ジャックポットのプールと宝くじの保存則**(フェーズ C-3a で新規) — 口座の保存則(5 点目の `Chips + Escrow`)とは**別の**保存則が 2 本ある。
   (a) **プール**: `economy.Jackpot` が動くのは 3 経路だけ — スロットの積立(`accrueJackpotLocked`)、7️⃣7️⃣7️⃣ の発火(全額支払い → 種 1,000 へリセット)、
   宝くじのハウス分の流入。積立はハウスの取り分から出るので**配当表もプレイヤーの控除も変えない**(だから既存の RTP テストは配当表不変のまま通る)。
   プールには上限 `MaxJackpot`(= `MaxChips` = 1e12)があり、**加算は必ず `creditJackpotCappedLocked` を通す** — 入り切らない分は捨てる。
   読み取り点(`seedJackpotLocked`)が `Jackpot` を `[JackpotSeed, MaxJackpot]` へ正規化するので、余裕 `MaxJackpot - Jackpot` 自体が桁あふれせず、
   加算は加える前にその余裕へ切り詰められる。手編集で `math.MaxInt64` が入っていても構造的にあふれない。
   端数 `JackpotAccum` は 1/100 チップ単位で常に [0, 100) — 負の値は Go の `/` と `%` がゼロ方向へ切り捨てるせいでプールを**減らす**ので、
   読み取り点(`seedJackpotLocked`)で 0 に戻す。
   (b) **賞金**: `LotteryPrize` は `prize = floor(sales×90/100) + carryover`、`house = sales − floor(sales×90/100)`。
   ハウス分を自前の `floor(sales×10/100)` にすると端数が消えるので、必ず**残り**として取る(`prize + house == sales + carryover` が全域で成り立つ)。
   支払いは `creditChipsCappedLocked` を通るので、当選者が `MaxChips` にいると `paid < prize` になりうる。その差額は
   **ハウス分と同じくプールへ送る**(`creditJackpotCappedLocked(economy, house + (prize − paid))`)。当選者がいた回の `Carryover` は必ず 0 —
   繰り越すとその人の賞金が次回の別の当選者へ渡り、消すとチップが消える。`Carryover` を使うのは当選者がいなかった回だけ。
   保存則の言い方は「通貨は消えない」ではなく「**プールの上限で入り切らない分だけが消え、それ以外の経路では消えない**」。
   (c) 順序: 宝くじのハウス分を足す前に**必ず種を入れる**。`creditJackpotCappedLocked` が内部で `seedJackpotLocked` を呼ぶのはこのため。
   逆順だと、C-3a 以前の 0 のプールに足した分が種への引き上げで丸ごと飲まれる。
   この領域の変更は段階に関わらず別文脈の評価者を通す。
