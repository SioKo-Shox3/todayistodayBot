## 2. 「所有権と寿命」

次の段落を `internal/casino.Default()` の段落の後ろに足す:

- `internal/casino.DefaultSessions()` はプロセス内シングルトンの `*casino.SessionManager` を返す(`sync.Once`)。
  **盤面(ハイ&ローの札列・ブラックジャックの手)はメモリにしか無く、永続化しない** — 賭け金は口座の `Escrow`
  (`data/casino.json`)にあるので、再起動で盤面が消えてもチップは消えない(起動時の
  `casino.Default().RefundStaleEscrows(now)` が全額返す)。`/highlow`・`/blackjack`・ボタンの
  `HandleComponent`・掃除人 goroutine は、すべて `DefaultSessions()` を経由して同一のマネージャ
  (=同一の `sync.Mutex`)を共有する。テストは `casino.NewSessionManager(clock, ttl)` で自分のマネージャを作る
  (`casino.New(tempDir)` と同じ理由で正しい)。
- 盤面の寿命は「最終操作から 3 分」(`casino.DefaultSessionTTL`)。期限を決めるのはマネージャ(`Sweep(now)`)で、
  その後の「`AutoResolve` → `SettleGame` → メッセージ編集」は `internal/commands/casino_sessions.go` が行う。
  掃除人は `cmd/bot/main.go` が起動する 2 本目の goroutine で、9 時掲示と同じ ctx で止まり、
  同じ理由(送信・編集の最中にセッションを閉じない)で `session.Close()` の前に終了を待つ。

## 3. 「スレッド / 並行性」

次の 1 項を足す:

- フェーズC-2 で並行の担い手が 3 つになった: interaction ハンドラ(Gateway の goroutine)・9 時掲示・掃除人。
  同じ盤面に対する競合は 2 段で閉じる — `SessionManager.mu`(盤面の適用そのもの)と、
  `internal/commands` の per-board ロック(`boardLocks`: 1 回の押下を「手を進める → 精算 → 返信」まで直列化し、
  未払いの精算を次の押下のために保持する)。**`SessionManager.mu` は再入不可**で `WithSession` の `fn` 実行中ずっと
  握られるため、`fn` からマネージャのメソッド・Discord 呼び出し・ディスク I/O・sleep を行ってはいけない
  (`casino.Store.SettleGame` は `WithSession` を**抜けてから**)。ロックの順序は常に「セッション → 抜ける → ストア」。

## 4. 「依存方向」

- `internal/commands/{highlow,blackjack,components,casino_sessions}.go` → `internal/casino`
  (`casino.Default()` と `casino.DefaultSessions()`)。
- `internal/casino/session.go` は **discordgo 非依存**を維持する(`MessageRef` は ID を 2 つ持つだけの値型)。
  Discord を触るのは `internal/commands` 側だけ — 掃除人のメッセージ編集も `internal/commands/casino_sessions.go` にある。
- `cmd/bot` → `internal/casino`(C-2 で追加。起動時の `RefundStaleEscrows` と、掃除人へ渡す
  `casino.Default()` / `casino.DefaultSessions()`)。

## 5. 危険地帯の 5 点目(新規)

5. **escrow の保存則と二重決着**(フェーズC-2で新規) — 賭け金は `Chips` と `Escrow` の間を動くだけで、合計
   `Chips + Escrow` が動くのは `SettleGame(payout)` のときだけ(`payout` は**預かりの返還を含む総額**。
   呼び出し側でベットを足さない)。ここが壊れるとチップが増殖するか、永久に「進行中」で固まる。守りは 4 枚:
   (1) 預け入れ(`OpenGame` / `AddToEscrow`)は同一口座内の移動なので通貨を作らない、
   (2) 決着した盤面は `WithSession` / `Sweep` が**マップから即座に消す**ので二度目の押下は `ErrSessionNotFound`、
   (3) それでも漏れたら `SettleGame` の `ErrNoGameInProgress`(`Escrow == 0` への精算を拒否)、
   (4) 盤面が死んだまま残った預かりは起動時の `RefundStaleEscrows` が返す。
   **盤面を閉じる経路(`Close`)は、押下と同じ per-board ロックを取ってから閉じること** — ⏫ ダブルは
   `AddToEscrow` をマネージャのロックの外で行うので、その途中で閉じると追加ベットが返らない。
   精算とメッセージの順序は常に「チップが先、表示が後」(失敗した編集を再試行して二重に払わないため)。
   この領域の変更は段階に関わらず別文脈の評価者を通す。
