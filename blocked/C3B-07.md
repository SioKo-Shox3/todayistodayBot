## 2. 「所有権と寿命」— 日次ロールオーバーで動くもの

「日次ロールオーバーは `ensureTodayRateIndexLocked` 1 箇所」の段落を **3 つ → 4 つ**に直し、
**(3) 宝くじの抽選の前**に次を入れる(番号は順に繰り下げる):

- (3) **月次シーズンの切り替え**(`rolloverSeasonLocked`。JST の**月初 0 時**で切り替わる。境界はレートと同じ深夜で、
  9 時ではない)。上位 3 名へ賞与を入れ、`LastSeason` を書き、**全口座の `SeasonNet` を 0 にし**、`SeasonMonth` を今月にする。
  未開始(`SeasonMonth == ""`)のギルドは賞与を配らず今月を開始するだけ(C-3b 以前の `data/casino.json` がこれに当たる)。
- 段落の末尾へ: 「**順序は「シーズンの切り替え → 宝くじの抽選」で固定**。切り替えは全口座の `SeasonNet` を 0 にし、
  抽選は当選者の `SeasonNet` を**加算する**ので、逆順にすると月境界と同じ呼び出しに当たった回の純利が毎月 1 日に消える
  (`TestStore_SeasonRollover_RunsBeforeTheLotteryDraw`)。この順序なら、その払い出しは開いたばかりの月に計上される
  = 消えない。月の比較は `SeasonMonth >= month` で早期に返す(`!=` ではない) — 時計が巻き戻っても、済んだ月を開き直して
  賞与を二度配ったり `SeasonNet` を二度消したりしない。」

## 3. 「危険地帯」7 点目

冒頭の「危険地帯は以下の6点(フェーズAの2点に、B・C-1・C-2・C-3aで1点ずつ追加)」を
「7点(フェーズAの2点に、B・C-1・C-2・C-3a・C-3bで1点ずつ追加)」に直し、次を 7 番目として足す:

7. **duel のゼロサムとシーズンの切り替え**(フェーズ C-3b で新規) — 5 点目(`Chips + Escrow` の保存則)と
   6 点目(プール・宝くじ)に、性質の違う 3 本が乗る。
   (a) **duel はゼロサム** — ハウスの取り分が無い唯一のゲーム。両者から `bet` を預かり、勝者へ `2 × bet` を払い、
   敗者は `payout = 0` で**明示的に**精算する(省略ではない。片方を精算し忘れると賭け金が `Escrow` に残り、
   その人はどのゲームも始められなくなる)。`FlipDuel` は `Intn(2)` **1 回**で、ここに控除を足すと
   「コイントスに胴元有利は作らない」(設計書 C-3b §2)が壊れる。精算は 2 口座を**同じ `Update`** の中で動かす —
   途中で保存されると片方だけ払われた状態がディスクに残る。`AcceptDuel` / `DeclineDuel` は
   `EscrowGame == GameDuel` を確認してから返金する: `Escrow > 0` だけで判定すると、挑戦が閉じた後に
   始めたブラックジャックの賭け金を盤面の下から二重に払う。受諾の失敗(残高不足・進行中あり)で
   **挑戦者の預かりは返さない** — 盤面は生きたままで、断られるか 3 分で失効したときだけ全額返る。
   (b) **シーズン賞与は意図的な新規発行** — デイリーボーナスと並ぶ、保存則の明示された例外。
   1 ギルドの 1 回の切り替えで最大 17,500 チップ(10,000 / 5,000 / 2,500)が湧く。支払いは必ず
   `creditChipsCappedLocked` を通し、上限で入り切らない分は捨てる(宝くじと違い、プールへ送る規則は適用しない —
   「他の 1 人へ移る」形にならないため)。`SeasonRank.Bonus` に記録するのは表の額ではなく**実際に入った額**。
   `SeasonNet` は**通貨ではない**(順位付けの集計値)ので、賞与自体を `SeasonNet` へ戻してはいけない —
   もらった賞与で翌月の順位が決まってしまう。
   (c) **切り替えは全口座を触る唯一の書き込み** — 他のすべての経路が 1〜2 口座しか触らないのに対し、
   ここはギルドの全 `Users` を走査して `SeasonNet` を 0 にする。したがって nil 口座(手編集の
   `{"users":{"someone":null}}`)は `topAssetsLocked` と同じく**飛ばす**(`ensureAccountLocked` で直すと、
   遊んでいない人にウェルカムボーナスを配ってしまう)。順位を取る前に `normalizeAccountLocked` を回すのも必須で、
   `SeasonNet` はそのまま `SeasonResult` へ写されるため、後から丸めても手編集の値がファイルに残る。
   この領域の変更は段階に関わらず別文脈の評価者を通す。
