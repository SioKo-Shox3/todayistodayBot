## 調べた設計上の結論(次の実装者への申し送り)

止める前に読み終えていたので、書ける形で残す。相手の差分と突き合わせて使えるはず。

- **消す機構は 3 つあった、2 つではない。** `WithSession` の `done`、`Close`(生きた盤面)、
  `Remove`(期限切れ = 掃除人のもの)。潰すべきは `done` で、`Close` / `Remove` の 2 つは
  **期限切れプロトコルの両半分**なので 1 つにはできない —
  `Close` は期限切れを拒否し(掃除人が精算中の盤面を取り上げないため)、`Remove` は期限切れを受ける。
  1 本にするなら「盤面を消すマネージャ呼び出しは `casino_shared.go` にしか現れない」という
  **ファイル単位の不変条件**にするのが正しい。相手が `Exists` を足しているのはこのため
  (door が期限切れ盤面を見られないと掃除人の分を通せない)。
- **押下決着の書き換えは `settleDealtHand`(`blackjack.go:443`)がそのまま雛形になる。**
  `MarkRefundPending(sessionID, payout)` で確定配当を盤面に固定 → `settle` → `closeBoardIfSettled`。
  印は「もう動かない盤面」の宣言でもあるので(`RefundPending()` の gate)、精算に失敗しても
  次の押下がポットを育てられない。H&L・BJ に同じ形を入れればよい。
- **`/duel` は既に適合している。** `accept` / `decline` は `closeBoardIfSettled` を通っており、
  `done=true` を返すのは `errDuelBadState` の 1 か所だけ。
- **`return true, errXBadState` を消すのは無害どころか改善。** 今の形は「State の型が違う」だけで
  盤面を消しており、預かりが残っていれば**それ自体が取り残しを作る**。error だけ返して盤面を残せば、
  掃除人が拾う。
- **構文木走査は `go/types` 無しで十分精密にできる。** AST から
  「型が `*casino.SessionManager` のフィールド名・引数名」を集め(`sessions` / `mgr`)、
  その識別子に対する `Close` / `Remove` の呼び出しだけを落とす。`reminder_test.go` などの
  `server.Close()` を巻き込まずに済み、複数行に折り返された呼び出しも AST なら形が変わらない。
