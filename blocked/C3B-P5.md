# C3B-P5 — 同じ作業ツリーで**ループランナーが2本**同時に走っている

反復 1(run-id `20260915-123431`)は C3B-P5 を実装できない。**別のランナーが同じ C3B-P5 を、同じ
作業ツリーで、今まさに書いている。** 実装を続けると相手の変更を上書きする。

## 何が起きたか(証拠)

`git status` は開始時点で `M NEXT_FINDINGS.md` だけだった。その後、こちらが触っていないファイルが
書き換わっていった:

```
$ ls -l --time-style=full-iso   (2026-09-15 12:37:53 時点)
internal/casino/session.go     2026-09-15 12:37:38
internal/commands/highlow.go   2026-09-15 12:37:37
internal/commands/blackjack.go 2026-09-15 12:37:42   ← 直前の git diff --stat には出ていなかった
```

プロセス一覧に**ランナーが2本**いる:

| PID | 起動 | コマンド |
|---|---|---|
| 58112 | 12:04:29 | `node ~/.agent-workflow/loop.mjs --repo . --engine claude --evaluate every --unattended` |
| 52512 | 12:34:31 | 同上 ← **この反復のランナー** |

それぞれに生きたエンジンがぶら下がっている(58112 → claude PID 20744(12:32:50 起動)/ 52512 → claude
PID 65476 = 自分)。`.harness/runs/` にも `20260915-120429` と `20260915-123431` が並んでいる。

12:04 のランナーは 12:32 に次の反復を起動しており、その反復が拾ったタスクも C3B-P5。作業ツリーは
1 つしかないので、2 つのエンジンが同じ 3 ファイルへ交互に書いている。

実際に衝突した: こちらが `internal/casino/session.go` へ `Session.RefundPending` フィールドを足した
直後、相手の書き込みがそれを消し、代わりに相手の設計(`ErrRefundPending` +
`func (s Session) RefundPending() bool { return s.PayoutResolved }` + 各ゲームでの拒否)が入った。
**こちらの編集は痕跡なく消えている**(`grep "RefundPending bool"` が 0 件)ので、今の作業ツリーは
相手の変更だけで一貫している。こちらからは以後 1 行も書いていない。

## 決めたいこと

**どちらのランナーを残すか。** 片方を止めない限り、どちらの反復も相手に上書きされ続ける。

## 選択肢

### A. 12:04 のランナー(PID 58112)を残し、こちら(PID 52512)を止める(推奨)

向こうは既に C3B-P5 の実装を 4 ファイル(`session.go` / `highlow.go` / `blackjack.go` / `duel.go`)まで
進めていて、こちらは 0 行。進んでいる側を生かすのが手戻りが最も少ない。
こちらのランナーは `LOOP_STOP` を置けば反復の切れ目で止まる(ランナーが消す)。
帰結: 費用ゼロ、可逆(いつでも起動し直せる)、失うものは無い。

### B. こちら(PID 52512)を残し、12:04 のランナーを止める

向こうの 99 行の未コミット変更を捨てるか、こちらが引き継ぐかになる。引き継ぐ場合、相手の設計
(`RefundPending()` が `PayoutResolved` を読む)が正しいかを先に検証する必要がある — このフィールドは
掃除人の `AutoResolve` も書くので、「返金待ち」と「掃除人が決着させた」が同じ値で表される。
帰結: 手戻りあり、判断が 1 つ増える。

### C. 両方止めて、1 本だけ起動し直す

一番安全だが、向こうの未コミット変更の扱いは B と同じ問題が残る。
帰結: 確実だが最も遅い。

## 推奨

**A。** 進んでいる側を生かし、こちらを止める。並行実行そのものが事故なので、再開は 1 本だけにする。

## 補足(A を採ったときに次の反復が見るべき点)

相手の `func (s Session) RefundPending() bool { return s.PayoutResolved }` は、`MarkRefundPending` と
掃除人の `AutoResolve` の**両方**が書く `PayoutResolved` を「返金待ち」と読んでいる。タスクの
`notes:` は「返金待ちは掃除人からは見えたまま」を求めており、期限切れ盤面は `Hold` / `Get` が
先に弾くので実害は出ない見込みだが、**2 つの意味が 1 つのフィールドに乗っている**点は評価者が
確かめる価値がある。
